# Current validation contracts

**Independent full-model numerical acceptance remains FAIL/open.** This guide covers maintained FP8 consumers, not historical CPU/BF16 commands. Historical measurements, thresholds and failures are preserved in [the validation archive](validation-history.md). Operational delivery is tracked separately in the [closeout checklist](spec-closeout-checklist.md).

All commands run from the repository root. Weights, tokenizer and reference fixtures are supplied locally; nothing is downloaded or regenerated by these commands. Use existing frozen, provenance-matched FP8 fixtures. Creating new references is separate work, not a way to replace failed goldens.

## Evidence layers

| Check | What it establishes / does not establish |
|---|---|
| Host/operator tests | Formats, guards, small numerical cases; not full-model acceptance |
| Frozen native regression | Same-operation bitwise consistency; native control is not an independent oracle |
| Independent FP32 reference | Full finite vectors under the fixed tolerance; known failures remain failures |
| Service/replay checks | State, authoritative IDs and publication; forced output has no task-success score |
| Free-greedy task checks | Exact frozen task criteria; not numerical correctness or general reliability |
| Matched-work timing | Only successful comparable work; not speed credit for failures/truncations |

Use [testing](testing.md) for model-free entrypoints. A model-free GPU test still uses the GPU. Optional stub/tokenizer integrations have separate dependencies.

## Current mixed-checkpoint validation

Only the official HF-layout single mixed FP8/BF16 model is supported. Archived BF16 oracles do not validate it. Independent expansion must reconstruct FP8 into FP32 times widened BF16 scale, without BF16 product rounding. Activation scales are checked, not used. Record exact model/tokenizer hashes, source revisions, fixture generator/library versions, precision/device/thread configuration, framing, token IDs, positions, cache trajectory, layouts and fixture hashes. The [reference index](../tools/reference/README.md) describes externally supplied artifacts; it is not a bundled generator or end-to-end reproducibility claim.

```sh
make build/compare_fp8
build/compare_fp8 models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  fixtures/fp8/decoded-sha256.txt
```

This optional macOS host-only consumer uses CommonCrypto SHA256, not GPU execution or a second full model. Supply one `tensor_name lowercase_sha256` line per each of 236 decoded text tensors, hashing contiguous little-endian FP32 output-major bytes. Duplicates/missing names reject. All 364 companion scale values are read/validated. Expected hashes must come from independent expansion, not the C implementation.

## Optional real-weight validation

Embedding comparison is bitwise, including signed zero:

```sh
make integration \
  WEIGHTS=models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  FIXTURES=fixtures/fp8
```

The four inputs are `embedding6.safetensors`, `embedding24.safetensors`, `embedding150.safetensors`, `embedding248.safetensors`. Each contains `input_ids` I64 `[1,N]` and `hidden_0` F32 `[1,N,3072]`. This checks embedding expansion/lookup, not the transformer, tokenization or full-checkpoint compatibility by itself.

## Full-model reference comparison

```sh
make BUILD=build/reference-check build/reference-check/compare_metal
build/reference-check/compare_metal --self-test
build/reference-check/compare_metal \
  models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  fixtures/prompt.ids fixtures/generation.safetensors
# Use a trailing --metal-prefill=custom for the separate custom-prefill check.
```

This consumer uses its fixed default resident/context 256 profile; it is not a compact/4352 acceptance command. `prompt.ids` contains 1..256 whitespace-separated decimal IDs. The independent reference safetensors contains:

| Tensor | dtype / shape |
|---|---|
| `generated` | I64 `[N]` |
| `logits_0` … `logits_N-1` | F32 `[1,131072]` |
| `block_25_STEP`, `final_norm_STEP` | F32 `[1,rows,3072]`; rows=prompt length at prefill, otherwise 1 |

`1 <= N <= 256 - prompt_count`; a numerical fixture therefore needs at most 255 prompt IDs, even though the runtime also accepts a full 256-token prefill. Reference trajectories must use actual cached decode, not repeated full-prefix recomputation. The comparator runs two reset cycles, checks all logits finite, requires exact lowest-index greedy IDs and applies `abs(error) <= 2e-4 + 1e-4*abs(reference)` to numerical comparisons. Multiple prompt/reference pairs can be supplied in one invocation. Additional invalid-ID, last-slot and destroy/recreate checks are state coverage, not extra independent numerical comparisons. Fixture provenance must be verified separately.

**Output-side effect:** this comparator writes failing `.f32` sidecars beside the fixture using fixed names and can overwrite those sidecars on a repeated invocation. Use a fresh run directory containing hash-verified copies of the supplied fixtures; do not run it against an immutable evidence directory or reuse an earlier output location. This does not regenerate or change the expected fixture contents.

Current strict FP8-derived longer-context discrepancies remain unresolved. Preserve nonzero exits, raw failed vectors and metrics; do not loosen the threshold or refresh expected values to erase them. Matching greedy IDs is insufficient. Run model processes sequentially; a final memory-guard refusal ends the run, not an invitation to bypass admission or retry. Never keep a reference Python model resident alongside the native model.

## Native and service regression

- [Frozen native regression](native-regression.md): operator controls and complete same-schedule model vectors. Capture/check are explicit and never update a reference implicitly. Existing full-model native consumers have their stated profile limits; do not infer compact/long-context coverage from them.
- [Controlled replay](controlled-replay.md): authoritative forced IDs, full logits, pending materialization and restoration; task success remains null.
- [Long-context runtime](long-context-testing.md) and [HTTP checks](long-context-http-testing.md): explicit fresh builds, supplied assets and bounded coverage.
- [Numerical evidence review](numerical-closeout-review.md): retained independent failures and limits, without a new automatic tracing campaign.

Changed reductions/partitioning need an explicit prospective comparison contract. Otherwise unchanged operations require bitwise native parity. Never equate a comparison to a provisional native control with independent numerical acceptance.
