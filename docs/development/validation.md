# Current validation contracts

**Independent full-model numerical acceptance remains FAIL/open.** Operational service delivery, native repeatability and task results do not close that gate. This page owns current comparator contracts; historical CPU/BF16 commands and trial results are not current validation instructions.

All commands run from the repository root. Weights, tokenizer and reference fixtures are supplied locally; nothing is downloaded or regenerated by these commands. Use existing frozen, provenance-matched FP8 fixtures. Creating new references is separate work, not a way to replace failed goldens.

## Evidence layers

| Check | What it establishes / does not establish |
|---|---|
| Host/operator tests | Formats, guards, small numerical cases; not full-model acceptance |
| Frozen native regression | Same-operation bitwise consistency; native control is not an independent oracle |
| Independent FP32 reference | Full finite vectors under the fixed tolerance; known failures remain failures |
| Service/replay checks | State, authoritative IDs and publication; forced output has no task-success score |
| Free-greedy task checks | Exact frozen task criteria; not numerical correctness or general reliability |
| Matched-work timing | Only successful comparable work; not speed credit for failures/truncations |

Use [testing](testing.md) for model-free entrypoints. A model-free GPU test still uses the GPU. Optional stub/tokenizer integrations have separate dependencies. Test comparators themselves with known matches and deliberate mismatches, including malformed and nonfinite inputs; a green parser/self-test is not real-model evidence.

## Current mixed-checkpoint validation

Only the official HF-layout single mixed FP8/BF16 model is supported. Archived BF16 oracles do not validate it. Independent expansion must reconstruct FP8 into FP32 times widened BF16 scale, without BF16 product rounding. Activation scales are checked, not used. Record exact model/tokenizer hashes, source revisions, fixture generator/library versions, precision/device/thread configuration, framing, token IDs, positions, cache trajectory, layouts and fixture hashes. Reference outputs, generator scripts and environments are externally supplied, not a bundled harness or end-to-end reproducibility claim. A supplied artifact must carry its provenance record; a standalone checkout does not imply that raw reference evidence is distributed.

```sh
make build/compare_fp8
build/compare_fp8 models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  fixtures/fp8/decoded-sha256.txt
```

This optional macOS host-only consumer uses CommonCrypto SHA256, not GPU execution or a second full model. Supply one `tensor_name lowercase_sha256` line per each of 236 decoded text tensors, hashing contiguous little-endian FP32 output-major bytes. Duplicates/missing names reject. All 364 companion scale values are read/validated. Expected hashes must come from independent expansion, not the C implementation.

## Optional real-weight validation

Embedding comparison is bitwise, including signed zero:

```sh
make integration \
  WEIGHTS=models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  FIXTURES=fixtures/fp8
```

The four inputs are `embedding6.safetensors`, `embedding24.safetensors`, `embedding150.safetensors`, `embedding248.safetensors`. Each contains `input_ids` I64 `[1,N]` and `hidden_0` F32 `[1,N,3072]`. This checks embedding expansion/lookup, not the transformer, tokenization or full-checkpoint compatibility by itself.

## Full-model reference comparison

```sh
make BUILD=build/reference-check build/reference-check/compare_metal
build/reference-check/compare_metal --self-test
build/reference-check/compare_metal \
  models/Ministral-3-3B-Instruct-2512-FP8/model.safetensors \
  fixtures/prompt.ids fixtures/generation.safetensors --strategy=resident-fp32
# Put --metal-prefill=custom before the final --strategy selector for custom prefill.
```

This consumer supports explicit resident, compact arithmetic and compact lookup selectors (see [strategy compatibility](#strategy-identity-and-compatibility)); omitted selection is deliberately fixed resident, not the product default. Context remains 256; this is not a 4352 acceptance command. `prompt.ids` contains 1..256 whitespace-separated decimal IDs. The independent reference safetensors contains:

| Tensor | dtype / shape |
|---|---|
| `generated` | I64 `[N]` |
| `logits_0` … `logits_N-1` | F32 `[1,131072]` |
| `block_25_STEP`, `final_norm_STEP` | F32 `[1,rows,3072]`; rows=prompt length at prefill, otherwise 1 |

`1 <= N <= 256 - prompt_count`; a numerical fixture therefore needs at most 255 prompt IDs, even though the runtime also accepts a full 256-token prefill. Reference trajectories must use actual cached decode, not repeated full-prefix recomputation. The comparator runs two reset cycles, checks all logits finite, requires exact lowest-index greedy IDs and applies `abs(error) <= 2e-4 + 1e-4*abs(reference)` to numerical comparisons. Multiple prompt/reference pairs can be supplied in one invocation. Additional invalid-ID, last-slot and destroy/recreate checks are state coverage, not extra independent numerical comparisons. Fixture provenance must be verified separately.

**Output-side effect:** this comparator writes failing `.f32` sidecars beside the fixture using fixed names and can overwrite those sidecars on a repeated invocation. Use a fresh run directory containing hash-verified copies of the supplied fixtures; do not run it against an immutable evidence directory or reuse an earlier output location. This does not regenerate or change the expected fixture contents.

Explicit strategy invocations write sidecars named `FIXTURE.MODE-STRATEGY-cycleN-stepN-TENSOR.f32`, including explicit resident. Legacy invocations without a selector retain `FIXTURE.MODE-cycleN-stepN-TENSOR.f32`; existing files are not renamed or relabelled. Repeated runs with the same mode/strategy names overwrite sidecars. Different explicit strategies cannot overwrite each other's outputs, but fresh run directories remain required. Actual strategy is queried from runtime memory accounting, reported and checked against the request (also on successful-path recreation).

Strict FP8-derived discrepancies in the 150/248-token short-profile cases remain unresolved; these are not independent 4352-token checks. Preserve nonzero exits, raw failed vectors and metrics; do not loosen the threshold or refresh expected values to erase them. Matching greedy IDs is insufficient. Run model processes sequentially; a final memory-guard refusal ends the run, not an invitation to bypass admission or retry. Never keep a reference Python model resident alongside the native model.

## Acceptance and discrepancy policy

Keep independent-reference checking, candidate-versus-control regression, service/state correctness, task behavior and performance separate. The native control is provisional, not an independent numerical oracle or a quality-approved baseline. Unchanged arithmetic requires full finite bitwise native parity, not only matching selected tokens or FP32 labels; preserve operation, rounding and reduction order. Declare a changed precision/reduction/partition contract prospectively before interpreting results. No relaxed native precision contract is implicitly approved.

Retain frozen independent checks and their strict failures. Establish an unchanged independent mismatch from comparable inputs, vectors, artifacts and error metrics, not equal failure counts. Known unchanged discrepancies do not automatically reopen numerical investigation or block authorized engineering. Separate infrastructure errors, absent coverage and new mismatches; never blanket-ignore nonzero comparator exits. Preserve raw mismatches and do not refresh goldens, retune prompts, widen tolerances or hide failed attempts behind retries.

Withhold acceptance for candidate/control contract regressions. Stop affected validation on nonfinite output, memory errors or invalid session/KV state; do not publish stale or partially valid KV. Flag new/materially worse independent discrepancies for review. A check is not authorization for an expanded cross-framework investigation: propose the new observation, suspected defect, discriminating experiment, stopping condition and decision impact before expanding scope.

Session/strategy validation must distinguish fresh versus resident execution, reset/recompute versus retained prefixes, buffered versus streamed token/text equality, continuation without omission or duplication, chunked ingestion, full vocabulary logits and relevant intermediates, near-capacity/overflow refusal and recovery without invalid state publication. State coverage is not a substitute for independent numerical comparison. Model-free service coverage must include parsing/bounds, transitions, busy/duplicate requests, framing/split UTF-8, cancellation/disconnect, slow clients, invalid operations/recovery and pending-token accounting with a deterministic generator; see [testing](testing.md).

Free-greedy tasks need frozen prospective task-specific criteria: correct calculation, supported lookup passage, required summary facts, structured fields or valid bounded tool completion. Preserve control failures and prompts. Protocol success is not task success; a failed task is not automatically an engine defect. Controlled replay has null task success. Freeze adaptively explored workloads before comparing policies.

Before an experimental comparison, freeze its hypothesis, identities, bounded shapes/workloads, memory/time budgets, comparator, meaningful performance criterion and stopping conditions; no open-ended tuning sweep or hidden failure retries. Keep defaults and memory-admission guards unchanged unless separately authorized.

For compact-storage optimization, compare against a compact control so storage changes cannot masquerade as kernel/fusion benefits. Resident FP32 remains supported and may answer a specific control question; it is not a mandatory cell in every experiment or permission to retain an unbounded expanded-weight cache. Declare scratch/lifetime bounds and test successive matrices/layers and shape changes. Validate components before isolated full-engine trials; only combine separately useful candidates after complete-workload evidence. For prospectively declared changed schedules in this experimental scope, retain finite checks and the existing elementwise bound `abs(error) <= 2e-4 + 1e-4 * abs(reference)`; neither a failed same-schedule bitwise check nor a changed algorithm authorizes widening it. These are acceptance safeguards, not authorization to restart parked experiments.

Performance requires successful matched work and settings: record source/model/tokenizer identity, strategy, prefill mode, capacity, chunk size and reuse policy. Separate load/conditioning from complete request/session latency, ingestion, first actual text, decode and pauses; include conversion, packing and synchronization. Keep tool time and cancellation response/completion separate, and do not combine sustained and intermittent observations. Use balanced repeated observations and retain raw samples, variability, timeouts, failures and resource refusals. Faster failed/truncated work is not faster success. Samples are not memory peaks; distinguish named engine buffers, process footprint and driver observations without double-counting unified memory. Capture/profiling timings are diagnostic, not headline speed evidence. Declare scratch allocation/lifetime bounds and report latency/memory tradeoffs; allocation counts alone do not establish DRAM traffic, occupancy or hardware utilization. Component improvements do not authorize integration or establish a complete-workload gain, and a candidate failing numerical/state or performance gates must not be promoted.

## Frozen operator regression

`make test` includes `make metal-reference-test` on macOS. This is offline, model-free GPU testing; no Python, model or network is required. A machine without a Metal device prints SKIP with zero GPU cases, not PASS.

The project/norm candidate comes from the same embedded production shader as the runtime. The reference is the independent, hash-pinned static source in `tests/frozen/`; it is never copied from the candidate during build or test. The two libraries use the production compile options. All non-NaN output bits must agree, including zero signs and infinities; NaN classifications, not payloads, must agree. Inputs and output guards must remain untouched. Exactly representable integer dot products provide an additional analytical oracle. Sizes include SIMD boundaries and tails and the 3072-wide model norm. This is not full-model numerical validation, nor an alternative CPU engine.

The unchanged-arithmetic contract is bitwise native parity. There is no approved relaxed native contract for future precision changes. The existing independent Python comparison remains `2e-4 + 1e-4*abs(reference)` and is not relaxed by these tests. DS4's model-specific top-K overlap limits and 8.0 score bound are not appropriate limits for Ministral and have not been adopted.

### One-operation diagnostic helper

For external, contiguous little-endian FP32 residual rows and FP32 norm weights:

```sh
make metal-norm-diagnostic INPUT=residual.f32 NORM_WEIGHTS=norm-weight.f32 \
  OUTPUT=new-output.f32 COLUMNS=3072 ROWS=248
```

This dispatches only the maintained custom norm kernel, using eps 1e-5, safe math and precise functions. It validates lengths, input immutability and output guards; output creation is exclusive. It does **not** judge numerical agreement. No device returns SKIP/77 (Make reports failure), so an automation must not count it as a pass.

The standalone test executable also accepts an explicit candidate-source argument for deliberate fault injection:

```sh
build/test_metal_reference tests/frozen/metal-baseline-v1.metal faulty-candidate.metal
```

Only the candidate may be overridden; a damaged/missing frozen source fails.

## Full-model native logit regression

`make native-self-test` is portable and included in `core-test` (also sanitize and NDEBUG). `make build/compare_native` builds the optional macOS model runner. Neither command captures or updates a reference. The runner uses only public runtime APIs, with no production instrumentation or dependency additions.

Explicit capture into an already-created **new empty directory**:

```sh
build/compare_native capture MODEL.safetensors mps NEW_DIRECTORY \
  FIXTURES/prefill6.ids FIXTURES/prefill6.safetensors \
  FIXTURES/prefill24.ids FIXTURES/prefill24.safetensors \
  FIXTURES/prefill150.ids FIXTURES/prefill150.safetensors \
  FIXTURES/prefill248.ids FIXTURES/prefill248.safetensors --strategy=resident-fp32
```

Use `custom` for the separate custom baseline. To check an already frozen reference with the maintained wrapper:

```sh
make native-regression WEIGHTS=MODEL.safetensors FIXTURES=FIXTURES \
  BASELINE=REFERENCE_DIRECTORY MODE=mps STRATEGY=resident-fp32
```

`FIXTURES` supplies `prefill6.ids`/`prefill6.safetensors`, `prefill24.ids`/`prefill24.safetensors`, `prefill150.ids`/`prefill150.safetensors` and `prefill248.ids`/`prefill248.safetensors`; ID files have exactly the named count of whitespace-separated decimal prompt IDs in vocabulary range, and each safetensors supplies `generated` I64 `[8]` in vocabulary range. Output files are `prefill6.bin`, `prefill24.bin`, `prefill150.bin` and `prefill248.bin`. Capture creates files exclusively; existing files fail, never overwrite. Freeze and hash the artifacts and provenance **before** invoking `check` in a fresh process with the same arguments and reference directory. `check` never writes a baseline and runs two reset cycles: 64 full vectors per mode. A third process can repeat the same check without recapture. Do not run two resident model processes concurrently. The unchanged production memory guard remains final; no retry, headroom change or fallback is permitted.

The eight `generated` IDs in each existing FP8 oracle fixture are used only for teacher forcing: prefill plus seven true cached decodes. Oracle logits are NOT copied. Native outputs alone form this regression reference. Missing or malformed IDs, steps, modes, context, shapes, formats and nonfinite vectors fail; no empty comparison or missing-file fallback succeeds. The complete trajectory must match. The binary format is fixed little-endian uint32 header/IDs and IEEE FP32 logits: magic `0x324e554c` (LUN2), strategy (0 resident / 1 arithmetic / 2 lookup), mode (0 MPS / 1 custom), context 256, prefix length, steps 8, vocabulary 131072, prompt IDs, eight forced IDs, eight full logit vectors. The four artifacts per mode contain about 16 MiB of full logits; keep captures in a separately owned artifact directory, not tracked engine source.

Acceptance for **unchanged Ministral arithmetic** is finite values on both sides, exact bitwise logits (score tolerance zero), identical top 1 and full top 5/20/64 sets at every step. Ties sort by increasing vocabulary ID. Per-step output reports finite counts separately, exactness, both top 1 IDs, top-K intersection counts, max absolute error, RMS and cosine with double accumulation. Bitwise repeatability must be established in separate processes before accepting this contract. This is not DS4's 8.0 score limit. An FP16 or other precision-changing candidate needs a separately agreed numerical contract; this test does not validate one.

A provenance manager should hash the entire checkpoint **before construction**, verify reference manifest/hash and all artifact hashes, and record separate reference/candidate source snapshots, environment, command, tokens and shapes. Do not require candidate source hashes to equal frozen reference source hashes: future candidate changes are the purpose of this test. Direct C commands validate the binary structure and trajectory, not JSON/SHA provenance; optional external stdlib tooling can supply that archival layer without making Python a runtime or portable test dependency. Capture must remain an explicit action, not a check side effect. Never auto-update a failed model baseline.

Offline file validation (no model/device needed):

```sh
build/test_native --files REFERENCE.bin CANDIDATE.bin mps 6 --strategy=resident-fp32
```

The offline build shares the exact C metrics/format reader with the model runner. Its unit tests cover known swaps, ties against an independent double rank oracle, nonfinite values, same-argmax changes outside top 64 and malformed headers/truncated vectors. Full-file negative validation should additionally preserve logs for NaN, Inf, top 1 swap, tail change, missing step, truncation, mode/token/context/shape/ format corruption and manifest hash corruption. These are logit/artifact mutations, not engine KV perturbations, and must not be described as KV injection.

These baselines are usable regression evidence, accepted on repeatability and component tests, not an independent full-model mathematical oracle. The existing strict Python comparator, failure logs and thresholds remain unchanged. Independent-reference coverage gaps and longer-case numerical disagreements remain open; neither native parity nor generated text establishes general correctness. No footprint, performance or benchmark claim is made.

## Strategy identity and compatibility

Both comparators accept a final `--strategy=resident-fp32`, `--strategy=compact-fp8-arithmetic` or `--strategy=compact-fp8-lookup`. Omission deliberately means fixed resident FP32, independent of the product default. Native capture/check and offline `--files` share this policy. `make native-regression` passes resident explicitly; `STRATEGY=compact-fp8-arithmetic` or `STRATEGY=compact-fp8-lookup` overrides it. Use separate reference directories per strategy and prefill mode.

Explicit-strategy native captures use LUN2. Legacy capture invocations without a selector retain LUN1 and fixed resident selection so existing LUN1-only provenance managers remain usable; they cannot capture compact strategies. New callers should always select explicitly. LUN1 (`0x314e554c`) has no strategy word and is interpreted exclusively as resident; its remaining layout is unchanged. Both formats are readable offline, including mixed-version resident pairs. Unknown formats, invalid strategy words and requested/artifact strategy mismatches fail; check validates every artifact before model construction. Native acceptance remains same-strategy strict finite bitwise parity, never automatic cross-strategy acceptance. Runtime memory queries report actual strategy and must match the request before execution.

Strategy binding does not add checkpoint hashes to the binary: the external provenance manager still owns model identity, source identity, precision, layout and environment checks. Context remains 256 with the existing fixed trajectories; compact selector support is not new numerical evidence or long-context/service coverage. Independent-reference comparison supports all three strategies with unchanged tolerances and teacher forcing, not native cross-strategy approval.

## Service and long-context comparisons

[Controlled replay](replay.md) checks forced trajectories, complete logits, pending materialization and restore while leaving task success null. [Long-context diagnostics](long-context.md) document optional fixed runtime and HTTP schedules, receipt requirements and remaining coverage gaps. Neither native cross-strategy parity nor same-schedule repeatability establishes independent long-context correctness. Run model processes sequentially; keep independent model generation separate from native execution. Memory admission refusals are final, not permission for hidden retries, changed guards or fallback.
